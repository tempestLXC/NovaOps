# 测试规范

本规范适用于 NovaOps 的所有模块，确保在 JDK 21（及后续版本）上具备可验证的质量与回归能力。

## 测试分层
- **单元测试**：覆盖业务核心逻辑，使用 JUnit 5/Mockito 等；避免依赖外部服务，必要时使用嵌入式或内存实现。
- **集成测试**：验证组件与中间件交互，可使用 Testcontainers 或嵌入式替身；避免引用商业闭源镜像或服务。
- **契约/接口测试**：对外提供的 API 需维护契约测试或 OpenAPI 校验，确保兼容性。
- **端到端测试**：关键用户路径需具备可重复的 E2E 测试脚本，推荐在 CI 中按需执行。
- **性能与容量测试**：关键链路在版本发布前执行基线对比，记录吞吐、延迟、资源占用，并保存测试数据与报告。

## 测试要求
- 新增功能必须附带相应测试；修复缺陷需包含回归用例。
- 重要模块建议单元测试语句覆盖率≥70%，并关注分支覆盖与边界条件。
- 测试数据需可重置且与生产数据隔离，不得包含真实隐私信息。
- 随代码变更更新测试文档，说明场景、输入、预期与清理步骤。

## 环境与工具
- CI/CD 使用 Maven 构建：`mvn clean verify` 作为默认校验命令，必要时增加 `-DskipTests` 说明理由。
- 数据库相关测试需自动迁移（如 Flyway/Liquibase）并在测试结束后清理或回滚。
- 日志、指标与追踪在测试环境与生产保持一致的格式与采集策略，便于对齐观测结果。

## 缺陷与回归管理
- 缺陷需附带复现步骤与影响评估；修复后补充回归测试并更新变更记录。
- 对历史问题的回归测试应纳入持续集成流水线，确保版本迭代中的稳定性。
